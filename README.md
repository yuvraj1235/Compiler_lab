# Compiler Design Lab – Solutions (C++)

All programs are written in **C++17** and compiled with `g++`. The three programs that the
question asks for in Lex/Flex or Bison (3, 10, 11) are `.l` / `.y` files whose actions are C++;
the code generated by Flex/Bison is compiled with `g++` as well. Every source file starts with a
comment containing **the exact question it answers**, a short note on the approach, and the
build/run commands.

## What is in this folder

| # | File | What the code does |
|---|------|--------------------|
| 1 | `01_two_buffer_input.cpp` | Two-buffer (buffer-pair) input system: `lexemeBegin` / `forward` pointers, sentinels, buffer reloads; detects keywords & identifiers |
| 2 | `02_scanner.cpp` | Scanner for a mini-C subset; tabular token output; skips whitespace/comments; line-numbered error reports |
| 3 | `03_token_lexer.l` | Flex program that prints token type + lexeme |
| 4 | `04_maximal_munch.cpp` | Longest-match (maximal munch) rule, shown with a rule-by-rule trace |
| 5 | `05_cfg_generator.cpp` | Generates a CFG and the language pattern `(aab)^n aa` for the input `aabaabaa` |
| 6 | `06_recursive_descent_ast.cpp` | Recursive-descent parser, AST, evaluation of `id + id * num` and `(id - num) / id` |
| 7 | `07_ll1_parser.cpp` | FIRST/FOLLOW, LL(1) table, table-driven predictive parser |
| 8 | `08_left_recursion_removal.cpp` | Removes left recursion (E, T, F grammar) and verifies the result is LL(1) |
| 9 | `09_lr0_parser.cpp` | LR(0) item sets, parsing table and shift/reduce parse of `abb` |
| 10 | `10_bison_config/` | Bison + Flex syntax checker / evaluator for a configuration language with variables |
| 11 | `11_bison_parentheses/` | Bison + Flex parentheses-balance and expression-structure validator / evaluator |
| 12 | `12_three_address_code.cpp` | Parser + Three-Address Code, Quadruples and Triples |

Sample inputs: `sample_input.src`, `sample_errors.src`, `10_bison_config/sample_ok.cfg`,
`10_bison_config/sample_err.cfg`, `11_bison_parentheses/sample_input.txt`.

## Prerequisites

| Tool | Needed for | Check with |
|------|-----------|------------|
| `g++` with C++17 support (GCC 7+) | every program | `g++ --version` |
| Flex | programs 3, 10, 11 | `flex --version` |
| Bison | programs 10, 11 | `bison --version` |

Install:

* **Ubuntu / Debian / WSL:** `sudo apt install build-essential flex bison`
* **macOS:** `xcode-select --install`, then `brew install flex bison` (put Homebrew's bison first on your `PATH`; the system one is very old)
* **Windows:** easiest is WSL (Ubuntu) with the command above, or MSYS2: `pacman -S gcc flex bison`

No other libraries are needed.

## How to run each program

Open a terminal in this folder (`compiler_lab_cpp/`).

### 1. Two-buffer input system
```bash
g++ -std=c++17 -Wall -o two_buffer 01_two_buffer_input.cpp
./two_buffer sample_input.src
```
Prints `[buffer] reloaded ...` every time a half is refilled, then a token table. The half size is
16 bytes by default so reloads are visible; `-DBUF_SIZE=64` changes it.
*Limitation (inherent to the scheme):* one lexeme must be shorter than one half.

### 2. Scanner (tabular output)
```bash
g++ -std=c++17 -Wall -o scanner 02_scanner.cpp
./scanner sample_input.src        # clean file
./scanner sample_errors.src       # lexical errors with line numbers
```

### 3. Flex token recogniser
```bash
flex -o lex.yy.cc 03_token_lexer.l
g++ -std=c++17 lex.yy.cc -o lexer
./lexer sample_input.src
```

### 4. Maximal munch
```bash
g++ -std=c++17 -Wall -o munch 04_maximal_munch.cpp
./munch                           # built-in test string
./munch "if (x<=y) z<<=2;"        # your own string
```
Each line lists every rule that matched, its length, and the winner.

### 5. CFG generator
```bash
g++ -std=c++17 -Wall -o cfg 05_cfg_generator.cpp
./cfg
```
Output: `S -> aab A`, `A -> aab A | aa`, language `L = { (aab)^n aa | n > 0 }`, a derivation of the
input and the strings for n = 1..5.

### 6. Recursive-descent parser + AST
```bash
g++ -std=c++17 -Wall -o rdp 06_recursive_descent_ast.cpp
./rdp                             # a + b * 4   and   (a - 4) / b
./rdp "a * (b + 3)"               # your own expression
```
Preset values: `a=10 b=5 c=2 x=7 y=3` (an unknown identifier is asked from you).

### 7. LL(1) table + predictive parser
```bash
g++ -std=c++17 -Wall -o ll1 07_ll1_parser.cpp
./ll1                             # accepted and rejected test strings
./ll1 abdcfe                      # your own string
```

### 8. Left-recursion removal
```bash
g++ -std=c++17 -Wall -o lrr 08_left_recursion_removal.cpp
./lrr
```
Result: `E -> T E'`, `E' -> + T E' | eps`, `T -> F T'`, `T' -> * F T' | eps`, `F -> ( E ) | id`.

### 9. LR(0) parsing table
```bash
g++ -std=c++17 -Wall -o lr0 09_lr0_parser.cpp
./lr0                             # parses abb
./lr0 abbb
```
**Note:** for `S -> A`, `A -> A b | a`, state I2 = `{S -> A. , A -> A.b}` has a shift/reduce
conflict in a *pure* LR(0) table (the reduce is placed on every terminal, including `b`). The program
prints that table, reports the conflict, then resolves it using FOLLOW(S) = `{$}` (SLR style) – the
table usually written in the textbook answer – and parses `abb` with it. Mention this in your viva.

### 10. Bison + Flex configuration-language checker
```bash
cd 10_bison_config
bison -d -o config.tab.cc config.y
flex -o lex.yy.cc config.l
g++ -std=c++17 config.tab.cc lex.yy.cc -o config
./config sample_ok.cfg
./config sample_err.cfg           # error recovery: syntax, undefined variable, divide by zero
```
Language: `name = expression;` and `print expression;` with `+ - * / %`, parentheses, `#` comments.

### 11. Bison + Flex parentheses / structure validator
```bash
cd 11_bison_parentheses
bison -d -o paren.tab.cc paren.y
flex -o lex.yy.cc paren.l
g++ -std=c++17 paren.tab.cc lex.yy.cc -o paren
./paren < sample_input.txt        # or run ./paren and type one expression per line
```
Per line it reports: balanced or not (unclosed `(` / extra `)`), maximum nesting depth, malformed
structure (`()`, `3 + * 4`, `2(3)`), division by zero, and the value when valid.

### 12. Three-Address Code, Quadruples, Triples
```bash
g++ -std=c++17 -Wall -o tac 12_three_address_code.cpp
./tac "a = b + c * d"
./tac                              # interactive mode, 'exit' to quit
```
For `a = b + c * d` it prints
```
t1 = c * d
t2 = b + t1
a  = t2
```
then the quadruple table `(op, arg1, arg2, result)` and the triple table `(op, arg1, arg2)` in which
temporaries are replaced by references such as `(0)`.

## Troubleshooting

* `config.tab.hh: No such file` – run `bison -d -o ...` **before** `flex` and `g++`.
* Run the Flex/Bison commands inside the program's own folder (10 or 11).
* Bison "conflicts" warnings – none are expected for programs 10 and 11.
* `error: ... requires C++17` – use `-std=c++17` (or `-std=c++14` is not enough for these files).
